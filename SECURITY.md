# CrabDeck Security Notes

This file exists because v2.1 had three real holes that matter a lot more once
this is reachable from the internet than they did on localhost. v2.2 fixes the
code-level issues; the items below still need a decision/action from you
before pointing hermes-claw.ai at a live instance.

## What v2.2 fixed

1. **Unauthenticated gateway (critical).** Any WebSocket client could send
   `HELLO {"client":"openclaw"}` and the gateway would believe it, then route
   real `TASK`/`PROMPT` traffic to it. Fixed: `HELLO` now requires a
   `GATEWAY_TOKEN` shared secret (generated by the installer, stored in each
   service's `.env`). A connection that doesn't present it stays in role
   `unknown` and can only `PING`.

2. **Unauthenticated → arbitrary shell exec chain (critical).** OpenClaw's
   `run_shell()` executed whatever command the LLM wrapped in `<CMD>...</CMD>`,
   with no auth in front of it and no allowlist. Combined with #1, this was an
   unauthenticated remote-code-execution path. Fixed:
   - Shell exec is now **off by default** (`ENABLE_SHELL_EXEC=0`).
   - When turned on, you can scope it with `SHELL_ALLOWLIST` (command-prefix
     allowlist).
   - It still trusts the gateway's auth, so #1 must stay enabled.

3. **CORS wide open (`allow_origins=["*"]`) on the orchestrator.** Fixed:
   now reads `ALLOWED_ORIGINS` (defaults to `http://localhost:5173`).

## What's still on you before going public

- **TLS.** Nothing here terminates TLS. Put the gateway (`ws://`) and
  orchestrator (`http://`) behind a reverse proxy (nginx/Caddy) doing
  `wss://` and `https://` on hermes-claw.ai, and only expose that, not the
  raw ports.
- **Token rotation/storage.** `GATEWAY_TOKEN` is a single static shared
  secret distributed to every service's `.env`. That's fine for "only my own
  agents connect," but it is not per-user auth — anyone who gets the token
  (e.g. via the UI's `.env.local`, which ships the token to the browser) has
  full bus access. If multiple humans will use this, put a real auth layer
  (session cookies, OAuth, whatever) in front of the UI/orchestrator and keep
  `GATEWAY_TOKEN` server-side only, with the UI talking to a backend proxy
  instead of holding the token itself.
- **`ENABLE_SHELL_EXEC`.** Leave it off on anything internet-facing unless
  you've scoped `SHELL_ALLOWLIST` tightly and you trust everyone who can
  reach the gateway with that token.
- **Rate limiting / abuse.** Nothing here rate-limits prompts or tasks. A
  single connected client can hammer Ollama or OpenClaw as fast as it wants.
- **Don't commit `.env` files.** `.gitignore` excludes them; only
  `.env.example` templates ship in the repo.
